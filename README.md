# Proxmox Cluster Dashboard - Complete Setup Guide

A modern, feature-rich dashboard for managing and monitoring Proxmox VE clusters with real-time statistics, advanced filtering, search capabilities, and beautiful visualizations.

## 🚀 Features

### Core Functionality
- **Real-time Monitoring**: Live cluster, node, and VM status tracking
- **Advanced Search**: Search across clusters, nodes, and VMs with instant results
- **Smart Filtering**: Filter by status, type, region, and version
- **Multiple Sorting**: Sort by name, status, CPU, memory, VM count, or region
- **Statistics Dashboard**: Comprehensive overview with charts and metrics
- **Health Monitoring**: System health score with progress and breakdown indicators
- **Notifications**: Automatic alerts for critical thresholds
- **Auto-refresh**: Optional automatic data updates (60s interval)

### Data Visualization
- **Interactive Charts**: Resource distribution and status charts using Chart.js
- **Health Score**: Progress indicator with component breakdown
- **Regional Statistics**: Breakdown by AMER, APAC, EMEA, and CME regions
- **Resource Metrics**: CPU, Memory, and Disk usage tracking
- **VictoriaMetrics Integration**: Quick links for node/VM CPU, RAM, Disk and Network observability
- **VM Analytics**: Running/stopped VM statistics

### Export Options
- **CSV Export**: Full cluster data for Excel analysis
- **JSON Export**: Complete data dump with statistics
- **HTML Report**: Formatted report for sharing

### User Experience
- **Dark Mode**: Beautiful dark theme with smooth transitions
- **Responsive Design**: Works on desktop, tablet, and mobile
- **Keyboard Shortcuts**: `/` to focus search, `Esc` to clear
- **Favorites**: Star clusters for quick access (coming soon)
- **Maintenance Alerts**: Display upcoming maintenance windows

## 📋 Prerequisites

- Web server (Apache, Nginx, or any static file server)
- Modern web browser (Chrome, Firefox, Edge, Safari)
- Proxmox VE 8.x clusters
- Network access to Proxmox clusters

## 🛠️ Installation

### 1. Download Files

Clone or download all files to your web server directory:

```bash
git clone <repository> /var/www/proxmox-dashboard
cd /var/www/proxmox-dashboard
```

### 4. Status Data Collection Script

You need to create a script (`proxmox-status.sh`) that generates `status.json`:

```bash
#!/bin/bash

# Example script structure (adapt to your environment)
# This should query all your Proxmox clusters and nodes

OUTPUT_FILE="/var/www/proxmox-dashboard/status.json"

# Start JSON
echo "{" > "$OUTPUT_FILE"
echo '  "lastUpdate": "'$(date -Iseconds)'",' >> "$OUTPUT_FILE"
echo '  "clusterStatus": {' >> "$OUTPUT_FILE"

# Query each cluster status
# ... your cluster status logic here ...

echo '  },' >> "$OUTPUT_FILE"
echo '  "nodeStatus": {' >> "$OUTPUT_FILE"

# Query each node status
# ... your node status logic here ...

echo '  },' >> "$OUTPUT_FILE"
echo '  "nodeData": {' >> "$OUTPUT_FILE"

# Query each node data (CPU, memory, VMs, etc.)
# ... your node data collection logic here ...

echo '  }' >> "$OUTPUT_FILE"
echo "}" >> "$OUTPUT_FILE"
```

#### Example status.json structure:

```json
{
  "lastUpdate": "2026-02-09T15:30:00Z",
  "clusterStatus": {
    "us-nyc1-prod": "online",
    "sg-sin1-prod": "online",
    "nl-ams1-prod": "degraded"
  },
  "nodeStatus": {
    "node1.us-nyc1-prod.example.local": "online",
    "node2.us-nyc1-prod.example.local": "online",
    "node3.us-nyc1-prod.example.local": "offline"
  },
  "nodeData": {
    "node1.us-nyc1-prod.example.local": {
      "cpu": 0.45,
      "mem": 68719476736,
      "maxmem": 137438953472,
      "disk": 107374182400,
      "maxdisk": 536870912000,
      "uptime": 2592000,
      "pveversion": "8.4.8",
      "vms": [
        {
          "vmid": 100,
          "name": "web-server-01",
          "status": "running",
          "cpu": 0.12,
          "mem": 4294967296,
          "uptime": 604800,
          "nautobotStatus": "exist",
          "nautobotVisible": true,
          "nautobotUrl": "https://nautobot.expereocloud.com/virtualization/virtual-machines/3f59473f-1de8-4a21-93e4-a6ed637cc3f6/"
        }
      ]
    }
  }
}
```

Optional per-VM fields for Nautobot integration:
- `nautobotStatus`: `exist`, `missing`, or `unknown` (recommended).
- `nautobotVisible`: `true`/`false` compatibility flag (optional, derived from `nautobotStatus` when omitted).
- `nautobotUrl`: direct URL for the VM record in Nautobot (optional, fallback URL is generated from VM name).

To avoid client-side Nautobot API calls on each dashboard refresh, run `nautobot-status-enrich.sh` after your Proxmox collection step:

```bash
# 1) Generate status.json from Proxmox
./proxmox-status.sh

# 2) Enrich VM records with Nautobot status
# Uses CONFIG.nautobot.baseUrl/apiPath/apiToken from ./config.js by default
./nautobot-status-enrich.sh /var/www/proxmox-dashboard/status.json

# Optional: override config.js values with environment variables
NAUTOBOT_BASE_URL="https://nautobot.example.com" \
NAUTOBOT_TOKEN="YOUR_READ_ONLY_TOKEN" \
./nautobot-status-enrich.sh /var/www/proxmox-dashboard/status.json
```

> `nautobot-status-enrich.sh` first reads `CONFIG.nautobot.baseUrl`, `CONFIG.nautobot.apiPath`, and `CONFIG.nautobot.apiToken` from `config.js`.
> Environment variables (`NAUTOBOT_BASE_URL`, `NAUTOBOT_API_PATH`, `NAUTOBOT_TOKEN`/`NAUTOBOT_API_KEY`) override values from `config.js`.
> The script can parse `config.js` directly even when `node` is not installed on the host.


Optional VictoriaMetrics fields in `status.json`:
- `victoriaMetrics.enabled`: runtime enable/disable from data source.
- `victoriaMetrics.baseUrl`: runtime VictoriaMetrics URL override.
- `victoriaMetrics.coverage`: object with `clusters`, `nodes`, and `vms` counters for dashboard display.
- `victoriaMetrics.queries`: optional query overrides (`nodeCpu`, `nodeMemory`, `nodeDisk`, `nodeNetwork`, `vmCpu`, `vmMemory`).

### 5. Configure Web Server

#### Apache

```apache
<VirtualHost *:80>
    ServerName proxmox-dashboard.example.com
    DocumentRoot /var/www/proxmox-dashboard
    
    <Directory /var/www/proxmox-dashboard>
        Options -Indexes +FollowSymLinks
        AllowOverride None
        Require all granted
    </Directory>
    
    # Enable gzip compression
    AddOutputFilterByType DEFLATE text/html text/plain text/xml text/css text/javascript application/javascript application/json
</VirtualHost>
```

#### Nginx

```nginx
server {
    listen 80;
    server_name proxmox-dashboard.example.com;
    root /var/www/proxmox-dashboard;
    index index.html;
    
    location / {
        try_files $uri $uri/ =404;
    }
    
    # Enable gzip
    gzip on;
    gzip_types text/plain text/css text/javascript application/javascript application/json;
    
    # Cache static assets
    location ~* \.(css|js|jpg|png|svg)$ {
        expires 1d;
        add_header Cache-Control "public, immutable";
    }
}
```

### 6. Automate Status Updates

Add a cron job to update status.json regularly:

```bash
# Edit crontab
crontab -e

# Add this line to run every minute
* * * * * /path/to/proxmox-status.sh

# Or every 30 seconds (run twice per minute)
* * * * * /path/to/proxmox-status.sh
* * * * * sleep 30 && /path/to/proxmox-status.sh
```

## ⚙️ Configuration

### Custom Settings

Edit `config.js` to customize settings:

```javascript
const CONFIG = {
  // Data URLs
  dataUrl: 'clusters.json',
  statusUrl: 'status.json',
  maintenanceUrl: 'maintenance.json',
  
  // Production PVE version
  pveVersionProd: '8.4.8', // Update this as needed
  
  // Auto-refresh interval (milliseconds)
  autoRefreshInterval: 60000, // 60 seconds
  
  // Nautobot integration
  nautobot: {
    enabled: true,
    baseUrl: 'https://nautobot.example.com',
    virtualizationPath: '/virtualization/virtual-machines/',
    apiPath: '/api/virtualization/virtual-machines/',
    apiToken: '' // Optional; only needed by external enrichment scripts
  },

  // VictoriaMetrics integration
  victoriaMetrics: {
    enabled: true,
    useStatusData: true,
    baseUrl: 'https://pve-console.expereo.com/metrics'
  },

  // Alert thresholds
  thresholds: {
    cpuWarning: 80,          // percentage
    cpuCritical: 90,         // percentage
    memoryWarning: 85,       // percentage
    memoryCritical: 95,      // percentage
    diskWarning: 80,         // percentage
    diskCritical: 90,        // percentage
    loadAverageWarning: 8,   // 1-minute load average
    loadAverageCritical: 10  // 1-minute load average
  }
};
```

> Set `nautobot.enabled` to `false` to disable Nautobot links/presence indicators in the UI.
> The dashboard now reads per-VM Nautobot status from `status.json` and does not call the Nautobot API from the browser.
> Set `victoriaMetrics.enabled` to `false` to hide the VictoriaMetrics panel entirely.
> Set `victoriaMetrics.useStatusData` to `true` to source the VictoriaMetrics panel configuration (enabled flag, base URL, coverage counters, and queries) directly from `status.json` (`victoriaMetrics` object).

### Country Flags

Update country flag mappings in `config.js` under `CONFIG.countryFlags`:

```javascript
countryFlags: {
  'your-cluster-name': 'us', // US flag
  'another-cluster': 'gb',   // UK flag
  // ... add your clusters
}
```

Flag codes use ISO 3166-1 alpha-2 format.

## 🐛 Troubleshooting

### Common Issues

**1. "No cluster data available"**
- Check that `clusters.json` exists and is valid JSON
- Verify file permissions (should be readable by web server)
- Check browser console for errors

**2. "Failed to load data"**
- Verify `status.json` is being generated correctly
- Check that the status update script is running
- Ensure web server can read the file

**3. "Nodes showing as offline"**
- Verify node names match between `clusters.json` and `status.json`
- Check domain suffix handling (with/without `.expereo.local`)
- Review node status collection logic in your script

**4. Charts not displaying**
- Ensure Chart.js CDN is accessible
- Check browser console for JavaScript errors
- Verify statistics section is enabled

### Debug Mode

Open browser console (F12) to see detailed logs:
- Data loading status
- API errors
- Cache status
- Event handling

## 📊 Performance Tips

1. **Enable Caching**: Data is cached automatically, adjust TTL in `config.js`
2. **Optimize Images**: Use compressed flag images
3. **Enable Compression**: Configure gzip in your web server
4. **CDN**: Use CDN for Chart.js and Font Awesome
5. **Auto-refresh**: Enable only when needed to reduce server load

## 🔒 Security Considerations

1. **Authentication**: Place dashboard behind your organization's SSO/auth
2. **HTTPS**: Always use HTTPS in production
3. **API Keys**: If using Proxmox API directly, secure your keys
4. **CORS**: Configure appropriate CORS headers if needed
5. **File Permissions**: Ensure only web server can read data files
